# Hermes 0.22.5 standalone upgrade

Chart 2.1.0 changes the default agent runtime from a floating public image to
`docker.io/nousresearch/hermes-agent:v0.22.5@sha256:9c5561579f3ffdf333401797094ac3a743738d6c25d40f4331c7bf77b694238d`.
This is the public K3s/standalone path. The PaaS image is a separate private
derivative with a different digest and is intentionally not used here.

## Before upgrading

1. Finish active conversations and back up the agent PVC using the cluster's
   normal snapshot procedure.
2. Record the running image and export the release values with
   `helm get values RELEASE -n NAMESPACE -o yaml`.
3. Confirm the exported file retains the existing `instance`, PVC claim names,
   Secret references, domains, extra containers, RBAC, and storage classes.
4. Render/diff with the real values and out-of-band placeholders. Do not commit
   credentials or substitute chart defaults for an existing instance.

The chart does not rename or delete PVCs and keeps `Recreate` strategy for the
single-writer agent volume. `secrets.create` remains false by default, so the
upgrade references existing Secrets rather than replacing them.

## Optional plugin source locks

The release lock contains:

| Plugin | Tag | Commit | Bundled runtime |
| --- | --- | --- | --- |
| hermes-paseo | v0.1.5-rc.3 | `7b9c88d032672f688c88df222e384ce3bc1af2f2` | `0.11.2-r3-523d451cc096` |
| hermes-omnigent | v0.1.0-rc.21 | `84e0c41ce91594908a53c91fcff09123ca92f626` | `omnigent-0.20.0` |

`scripts/stage-optional-plugins.py` downloads by commit, verifies the archive
SHA-256 and `plugin.yaml`, rejects links/path traversal, and atomically writes a
new staging directory. It never accesses `$HERMES_HOME`. Installation,
enablement, Dashboard reload, credentials, engine approval, and pairing remain
manual. Do not overwrite an installed plugin or its `plugin-data`; use its
documented upgrade procedure. Hermes 0.17.4 must not be used for Paseo: the
locked candidate was validated with Hermes 0.22.5 and Paseo 0.11.2.

## Rollback

Roll back the Helm release revision or explicitly restore the prior image value
while continuing to pass the saved release values and placeholders. A runtime
rollback does not justify deleting the PVC, Secret, plugin source, or
`plugin-data`. If a plugin was manually upgraded, follow that plugin's own
rollback procedure; do not infer plugin rollback from the Helm revision.

## Release recipe (not executed by this repository change)

1. Run `bash tests/runtime-release-contract.sh` and
   `python3 tests/plugin-release-contract.py`.
2. Run the complete chart workflow from `.github/workflows/lint.yml`, including
   `helm lint`, all instance renders, schema validation, and `helm package`.
3. Build with `./docker/build-image.sh`, inspect the resulting base-image
   provenance, and push only under a new immutable registry tag/digest.
4. Package chart 2.1.0, record its archive SHA-256, and publish only after PR
   approval. Chart publication and custom-image publication are separate acts.
5. Stage each optional plugin once from the lock and record its generated
   `WOOWTECH-SOURCE-RECEIPT.json`; do not install or pair it as a release step.
